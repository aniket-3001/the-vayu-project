Several problems I expected to need custom code became one setting or one call.

1. Amazon DynamoDB: a race-safe quota in one operation. The assistant has a daily limit: 40 questions per caller, 500 in all. Read-check-increment has a race: two requests at once can both read zero and both go ahead. One conditional UpdateItem (ADD count 1, condition count < limit) makes it atomic, and a failed condition is the "you are at your limit" answer. No lock, no mutex service, no extra table. TTL deletes yesterday's counters, and on-demand mode meant nothing to size for a demo with unknown traffic.

2. AWS CDK: safety rules as failing builds. CDK assertion tests read the synthesized template before anything deploys. "Every Lambda on arm64", "no function time limit over 2 minutes", "every bucket blocks public access", "only /v1/me uses the JWT authorizer", "only one policy may grant states:SendTaskSuccess" and "no secret value in an environment variable" are all tests. If I, or a library update, break one, make prove fails before anything is uploaded.

3. Amazon Bedrock Converse with Guardrails in one call. The guardrail rides inside the Converse request, so there is no second call to orchestrate, and stopReason tells my code when it stepped in, so the fallback to the rules' own text needs no timeout or extra state. With the trace on for one test call, the response listed the text units and tokens used. That is how I know a question costs about $0.0008 and 98% of it is the guardrail, so the caps went on the assistant. It gave me a measured cost from a real call, not an estimate.

4. Amazon CloudFront cache policies: the API controls its own cache. With minimum and default TTL 0 and maximum 15 minutes, the API decides per answer through cache-control, and an answer without one, such as an error, is never kept. A repeat lookup returns in about 0.15 s, against a median 1.5 s in Lambda for a fresh one, and I wrote no caching code.

5. AWS Systems Manager Parameter Store as a kill switch. The assistant runs only while one parameter is exactly "true"; any other value, or a failed read, means off, so it fails closed. One command stops all model spend within a minute, with no deploy. If the model does something odd at 2 am, that is the whole remedy.

6. Amazon EventBridge Scheduler: retries are a setting. I set them to zero on both jobs. A harvest that fails at 8:00 waits for 8:15 instead of retrying into a pile-up that eats the provider's rate limit. It is one line of CDK, and a test holds it.

7. Amazon Polly and Amazon Cognito. One neural voice, Kajal, reads English and Hindi, which is what a Delhi household speaks. Cognito with the API Gateway JWT authorizer gave me accounts with no token-checking code of my own: the function reads the user id from the verified claims and keys one DynamoDB item on it.

8. AWS Price List API. It gave me the ap-south-1 list prices, so every line of my cost model can be checked against its source, and the guardrail's share of the assistant's cost was obvious in the breakdown.
