I built The Vayu Project solo, and used Claude (Anthropic's AI coding assistant) as a pair programmer, the way many engineers now work. I set the problem, the architecture and the rules, directed every change, and read, ran, tested and deployed all of it on AWS myself. The hardware I built by hand.

Product decisions. I decided what the app may and may not say, and wrote those decisions as sixteen rules, each with a place in the code that enforces it and an automated test that fails if it breaks. The main one: code decides the advice, and the model may only word it, checked in code. A reading older than six hours gives no advice. A GRAP band is always my estimate, and a school is only ever "likely" closed. Every public claim sits in a ledger with what supports it.

Cloud. One CDK stack in my own AWS account: CloudFront, S3, API Gateway, Lambda, DynamoDB, EventBridge Scheduler, Bedrock with a Guardrail, Polly, Cognito, Secrets Manager, Systems Manager, CloudWatch and Step Functions. I ran every deploy from my machine and put the provider keys into Secrets Manager from the clipboard, never into a chat. When OpenAQ rejected my key late on 10 October, I replaced it and confirmed the map job read monitors again. I priced every metered thing from the AWS list prices before setting a cap (about $4.50 a month idle, $0.0008 an assistant question), and measured the live API: a median 1.5 s in Lambda on a fresh lookup (p99 5.2 s), about 0.15 s from CloudFront on a repeat.

Hardware. I sourced and wired a Sensirion SPS30 particle sensor to an ESP32-S3 over UART and flashed the 186 lines of firmware that send a Bluetooth packet every 2 seconds. When the sensor went silent as soon as the app connected, I read the serial log, found it, and the firmware now restarts the sensor on connect and after three failed reads. On 11 October it showed my room at 18 to 22 µg/m³ PM2.5, on the serial monitor and on the live site. I also built a prototype cleaner from about ₹5,000 of parts and measured its outlet airflow at about 191 cfm with a handheld anemometer.

Quality. 1,285 automated tests, lint, strict types, cdk synth and a bundle check run in one command before anything ships, plus a smoke test and browser scripts against the live address. I found faults the tests did not: my own screenshot showed AQI 500 beside "GRAP Stage II". I traced it to the estimate using the last 24 hours the monitor had, fixed it, and checked it against the monitors' own readings on 24 station-days (22 matched, 2 had too little data).

What I learned. Give the model the smallest job, then check it in code: every failure I had with it sat where that line was loose (a guardrail that blocked my own instruction, a masked name read as the number 1, a live answer that called AQI 61 "good"), and each is now a test. Real AWS finds what tests do not: a forwarded Host header, a rollback that failed, a model id refused in my region. Price every metered thing before you set a cap. Read your own screenshots as a stranger would. And write down what you measured and what you did not; it changed what I let the app claim.
