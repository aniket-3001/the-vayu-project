# Threat model

What could go wrong, who would do it, what stops it today, and what is left. Written from the code and the docs as of this
commit; it has had **no outside review**. A reviewer who did not build the app should go through it before a public launch
(see `PRODUCTION-CHECKLIST.md`).

## What is worth protecting

| Asset                                       | Why it matters                                                                            |
| ------------------------------------------- | ----------------------------------------------------------------------------------------- |
| People's saved places, family, outdoor time | Where a family lives and where children go to school. Held in DynamoDB under the account. |
| Accounts (email, password)                  | Passwords are held by Cognito; our API never sees them.                                   |
| The advice itself                           | Wrong advice about air is a health matter. Rules decide it; the model only rewords.       |
| The AWS bill                                | A public app with a paid model behind it can be run up.                                   |
| The provider keys                           | OpenAQ, NASA FIRMS, Telegram. In Secrets Manager.                                         |
| The admin statistics                        | Usage data. Two owners only.                                                              |

## Who might attack

An anonymous visitor with a script; a curious signed-in user trying other people's data; someone who finds the raw API address;
someone trying to make the assistant say something harmful; a person who obtains a phone or a laptop with a session on it.

## Threats

| #   | Threat                                                                                                       | What stops it now                                                                                                                                                                                                                  | What is left                                                                                                                                                                              | Plan                                                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| T1  | A script floods the API to run up cost                                                                       | API Gateway throttle (25/s), tighter on paid routes; daily caps (40 per caller, 500 total for the assistant); kill switch                                                                                                          | No limit per address at the edge; a flood against CloudFront itself is uncapped                                                                                                           | `EdgeStack` (web firewall) is written, not deployed                                                          |
| T2  | A caller dodges the per-caller limit by calling API Gateway directly and forging `CloudFront-Viewer-Address` | The whole-day caps still hold                                                                                                                                                                                                      | The per-caller limit can be dodged                                                                                                                                                        | Origin secret is written, off by default (`-c originSecret=on`)                                              |
| T3  | Prompt injection: the visitor tells the assistant to ignore its rules                                        | Rules decide; the model only rewords or answers from given facts; fixed system prompt; guardrail; every number checked against the facts; forbidden patterns; on any doubt the plain rule text is sent. Hindi never uses the model | A true number in the wrong place passes the check; a wrong word the patterns do not know                                                                                                  | Keep adding patterns when the live checks find one; log refused answers                                      |
| T4  | The assistant leaks the family's names or place                                                              | Names are masked before the model sees them and put back after                                                                                                                                                                     | The question text itself goes to the model after masking                                                                                                                                  | Review what the masking misses (nicknames, street names)                                                     |
| T5  | One user reads or changes another's saved data                                                               | API Gateway checks the Cognito token; the user id comes from the verified claims, never from the body                                                                                                                              | Not tested against a second real account                                                                                                                                                  | Add an end-to-end test with two accounts                                                                     |
| T6  | Password guessing or credential stuffing                                                                     | Cognito's own lockout and throttling                                                                                                                                                                                               | No multi-factor sign-in. Sign-in now uses SRP (the password is not sent), but the older `USER_PASSWORD_AUTH` stays on until old phone apps are retired                                    | Turn the old flow off once `minAppVersion` retires old builds; build optional MFA (checklist)                |
| T7  | Theft of a session from a lost phone or a script on the page                                                 | Tokens expire; strict content policy blocks other scripts; HTTPS only                                                                                                                                                              | On the website the refresh token is in `localStorage`, readable by any script that runs on the page. In the phone apps it is now in the Keychain/Keystore (not yet tried on a real phone) | Test on real phones; keep the strict script policy on the website                                            |
| T8  | A script injected into the page (XSS)                                                                        | React escapes by default; strict content security policy; no framing                                                                                                                                                               | Scripts are `'self'` only (good), but `style-src` allows `'unsafe-inline'`, which permits injected styles (a smaller risk than scripts)                                                   | Move inline styles to classes or nonces, then drop `'unsafe-inline'` from `style-src` in `infra/lib/Site.ts` |
| T9  | Someone reads the admin statistics                                                                           | The API checks the token's email against the owners' list                                                                                                                                                                          | The list is set at deploy time; no audit log of who opened it                                                                                                                             | Log admin reads                                                                                              |
| T10 | A leaked provider key or committed secret                                                                    | Secrets Manager; gitleaks in CI                                                                                                                                                                                                    | Keys on a developer's machine                                                                                                                                                             | Rotate on any doubt                                                                                          |
| T11 | A poisoned dependency                                                                                        | Lockfile; `npm audit` in CI; Dependabot; CodeQL                                                                                                                                                                                    | No signature check; install scripts run                                                                                                                                                   | Pin the CI actions by commit hash                                                                            |
| T12 | A bad deploy or a provider outage shows wrong air                                                            | The app shows the age of every reading, drops monitor data older than six hours, says "Estimate" for the model, and gives no advice from stale data                                                                                | A provider returning plausible wrong values would pass                                                                                                                                    | Cross-check a reading against the model and flag large gaps                                                  |
| T13 | The device (Bluetooth unit) is spoofed                                                                       | It talks only to the phone in front of it; readings stay on the device                                                                                                                                                             | Anyone near the unit can connect; no pairing check                                                                                                                                        | Document; low impact                                                                                         |
| T14 | Personal data kept longer than needed                                                                        | Item expiry on tables; account deletion removes the copy and the timeline                                                                                                                                                          | Retention is not published as a policy                                                                                                                                                    | `docs/PRIVACY-POLICY.md`                                                                                     |
| T15 | Abuse of the request and fire-report forms (spam, personal details)                                          | Validation; per-caller and daily limits; kept 180 days; never sent to anyone                                                                                                                                                       | A shared daily cap can be used up by one script                                                                                                                                           | Web firewall rule on these routes                                                                            |

## Order to fix

1. T1, T2: deploy the web firewall and the origin secret.
2. T6, T7: SRP sign-in, MFA, secure token storage.
3. T5: a two-account test.
4. T8, T11: review the content policy; pin the CI actions.
5. Outside review of all of this.
