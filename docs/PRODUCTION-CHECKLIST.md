# Production-readiness checklist

Living list of what a widely used app has that ours lacks. Tick an item only when it is done **and verified**; put the
evidence (test, file, command) beside it. Items marked `[you]` need a person with AWS, Apple or Google access: code
cannot finish them. Sources: `AS-BUILT.md` known limits, `architecture.md` pillars, `cost.md`.

## Phase 1: quick, high value

- [x] Alarm email subscribed and confirmed (2026-11-05, deployed with `-c alertEmail=…`), so alarms now reach a person.
- [x] Permission-string lint: every permission the web or native code uses has an iOS usage string and an Android permission. `tests/lint/permissions.test.ts` (runs in `npm test` and CI).
- [~] Origin secret: CloudFront adds a secret header, the API refuses requests without it, so the per-caller limit cannot be dodged by calling API Gateway directly. Code, tests and synth done (`apps/api/src/originGuard.ts`, `infra/test/VayuStack.test.ts`); **Switched on 2026-11-05** (`-c originSecret=on`): the direct `execute-api` address now answers 403 and the CloudFront address works. - [x] Client crash reporting through Sentry, **live on the website since 2026-11-05** (EU project; `crashReportingHost` in `infra/deploy.local.json`, DSN given when running `scripts/deploy-site.sh`). `apps/web/src/crashReporting.ts` sends no person, address, request or breadcrumbs and scrubs coordinates. Phone apps: give `sentry_dsn` when starting the android-debug workflow. Source maps: built and tested but **off until you give a token** (see `docs/RUNBOOK.md`); until then stack traces in Sentry stay minified. Session replay, tracing and logs are off on purpose.

- [x] Vulnerabilities from `npm audit --omit=dev` fixed where a fix exists: zod migrated to 4.6.7 (was high), react-router-dom upgraded to 7.18 (was moderate; the 740 web tests and the build pass). The two that remain are moderate, in the CDK build tool (`aws-cdk-lib`'s `minimatch`), used only when deploying, with no fix available yet; CI fails on high.
- [x] `SECURITY.md`: how to report a vulnerability, security contact.
- [x] Smoke test and the web app's development fallback default to the CloudFront address, not `execute-api` (`tests/smoke/live.ts`, `apps/web/src/config.ts`). Still `[you]`: rebuild and reinstall any phone build made before this that was pointed at `execute-api`.

## Phase 2: security and operations

- [~] AWS WAF on CloudFront: `infra/lib/Edge.ts` (per-address rate limits, harder on the assistant and voice routes, plus AWS's IP-reputation, known-bad-input and common rule sets), tested. **Deployed and attached 2026-11-05** (`VayuEdge` in us-east-1, then `Vayu -c webAclArn=…`). Every later `cdk deploy Vayu` must repeat `-c webAclArn=…`, or the firewall is detached. Watch the WAF metrics in CloudWatch for a week for false blocks.
- [~] Cognito sign-in now uses SRP (the password is never sent): `apps/web/src/account/srp.ts`, checked step by step against the official library, wired into `cognito.ts`, the pool client allows it. The old password flow stays enabled for phone apps built before this; `[you]` after the minimum app version has retired them, remove `userPassword` in `infra/lib/Accounts.ts`. **Verified 2026-11-05:** account creation and sign-in worked in the Android debug app against the live pool. Not yet tried on an iPhone. **MFA is not built:** it needs a second challenge screen and a choice of method (authenticator app or SMS), and a pool change.
- [~] Phone apps now keep the sign-in session (including the refresh token) in the iOS Keychain / Android Keystore instead of `localStorage`: `apps/web/src/account/secureSession.ts` with `@aparajita/capacitor-secure-storage`, native projects synced. Moves a session an earlier version left in browser storage, wipes a Keychain entry left by a deleted app, never uses iCloud Keychain, falls back to the old behaviour if the plugin fails. Tested with a stand-in plugin. **`[you]`: rebuild the phone apps, sign in, close and reopen, and confirm you are still signed in on a real iPhone and Android phone.** The website still uses `localStorage` (its protection is the strict script policy).
- [~] Staging stack: `cdk deploy VayuStaging -c stage=staging` makes a separate copy beside the real one (names that must be unique per account carry the stage; real names unchanged; tested). Deploy pipeline written but never run: `.github/workflows/deploy.yml` (checks, staging, then production behind a required approval) and `docs/DEPLOY.md`. `[you]`: create the AWS role and the GitHub environments described there, and run staging once. No automatic rollback yet.
- [x] Runbook: provider outage, kill switches, by-symptom table: `docs/RUNBOOK.md`. Still needed: a named person to call, and the commands tried once for real. `[you]`
- [x] SLO alarms: `ApiAvailability` (over 2% of requests answered with a server error across 15 minutes, ignoring quiet periods) and `ApiSlow` (p95 latency over 3 s for 15 minutes), alongside the existing stopped-job alarms for data freshness (`HarvestStopped`, `StationsStopped`). Tested in `infra/test/VayuStack.test.ts`. Thresholds are first guesses; tune them after a week of real traffic. Alarms reach no one until an email is subscribed (see the first item).
- [~] Cost anomaly detection added next to the budget (`AWS::CE::AnomalyMonitor` by service, a daily mail when an unusual jump costs $5 or more), created only when `alertEmail` is given and tested. `[you]` deploy with `-c alertEmail=...`. AWS allows **one** by-service monitor per account and usually creates `Default-Services-Monitor` itself; creating a second fails the whole deploy ("Limit exceeded", found on the first deploy). Pass the existing one with `-c spendMonitorArn=<its ARN>` (`aws ce get-anomaly-monitors --region us-east-1`).
- [~] Threat model written down: `docs/THREAT-MODEL.md` (15 threats, what stops each, what is left). Still `[you]`: an outside review or pen test before a public launch.

## Phase 3: quality and performance

- [x] Flaky `nativeSpeech.test.ts` fixed: it waited one timer tick for a dynamic import; it now waits for the call.
- [x] End-to-end tests of the built website in a real browser: `tests/e2e` (Playwright, phone-sized Chromium, API faked, served with the real content policy), `npm run e2e`, and an `e2e` job in CI. They check the app opens, a saved place shows its source, no content-policy violation on the main screens, and the last good reading survives a dead network. The fake API answer is checked against the real contract (`tests/e2e/mock.test.ts`). **Not covered:** the native shell (Maestro or Detox on a simulator), sign-in against a real pool, the map (headless Chromium has no WebGL) and the Lens (needs a camera).
- [ ] Real-device matrix: iPhone, Android, Bluetooth on each. `[you]` Maestro flows for the native shell are outlined in `docs/NEXT-STEPS.md` (section 6).
- [~] Automated accessibility checks (axe-core) on My Air, Exposure, Account and Room in `apps/web/src/a11y.test.tsx`; they found and fixed a real fault (place cards were list items given the button role, nesting links in a button). `[you]` still needed: colour contrast (jsdom cannot judge it), the map and Lens screens, and a pass with VoiceOver, TalkBack, Dynamic Type and reduced motion on real phones.
- [x] Route-level code splitting: the map and the Lens now load on demand. Main script 1,871 KB to 775 KB (the map's 1,071 KB loads only when the map is opened). Further: split Exposure and the recorded days, and check first-load time on a real phone.
- [x] Bundle-size budget: `scripts/check-bundle.mjs` fails `make prove` if the main script passes 900 KB (now 775 KB).
- [x] Offline: the last good reading of each place is saved on the device and shown at once after a restart, only while younger than three hours (the same limit the rules use for advice). In the same change the age on every card now keeps growing while a reading stays on screen (it used to freeze at the age it arrived with, which overstated freshness after a failed refresh). `apps/web/src/air/store.ts`, `storePersistence.test.ts`. Not done: a service worker so the app shell itself opens with no network on the website; the phone apps bundle the shell already.
- [~] Load test script `scripts/load-test.mjs` (read-only routes only, capped at 50 requests a second, needs `--yes`). `[you]` run it against the live address before a launch and record the numbers.
